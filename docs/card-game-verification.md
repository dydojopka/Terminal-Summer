# Проверка интеграции карточной игры

Среда: Linux x86-64, Python 3.14.10, зависимости из `requirements-dev.txt`.

## Регрессия

Повторный прогон **309 существующих тестов** завершился успешно.
Карточные наборы запускались отдельно с измерением покрытия; дополнительные
четыре теста `test_filter_preview.py` также прошли.
Карточная часть содержит **54 теста**: в последнем общем прогоне прошли
53; единственное падение было преждевременной проверкой размера кадра
после снятия загрузочного overlay. Проверка исправлена: она ограниченно
ожидает публикацию CPU-рендера нужного размера/стиля, затем делает прежние
строгие утверждения. После исправления этот тест прошёл отдельно.
Полный набор 54 тестов после последней правки только тестового ожидания
повторно не запускался; результаты не выдаются за единый зелёный прогон.
После финальной правки завершения приложения повторно прошли
**36 затронутых тестов** стилей, кэшей, фильтров и пропуска.
Закрытие приложения отменяет прогрев; его `finally` больше не обращается
к демонтированному UI. Три отдельных теста клавиатуры/закрытия/ошибки задачи
также прошли без необработанных исключений.

## Область проверки

- Оценка рук сверена с алгоритмом оригинала для всех **18 395** допустимых
  шестикарточных профилей номиналов и для 10 000 случайных раздач.
- Проверяются все семь фаз, три круга, стратегии трёх соперниц,
  перестановки, невозможные действия и сохранение уникальности карт.
- Матрица настоящего Textual runtime: **27 сочетаний**
  «ASCII / COLOR_ASCII / ANSI × Лена / Ульяна / Алиса × победа / поражение / ничья».
- Обучение использует TXT; проверяются остановки, раскрытие руки,
  блокировка ходов во время реплик и постоянная геометрия стола.
- Проверяются все четыре итоговых результата турнира, реванш Ульяны,
  обе ветки спора с Алисой и повтор каждой партии после ничьей.
- Меню пропуска проверяются для всех **16 сочетаний** четырёх флагов прогресса.
- Сериализация проходит JSON round-trip во всех фазах с сохранением RNG.
  Настоящие save/load проверяются и для обычных фаз, и для предложения
  Ульяны, и для реплики обучения. Повреждённые позиции отвергаются
  до сброса игры/аудио; потеря `cards` и тихое понижение формата запрещены.
- Проверяются клавиатура/мышь, история, пауза, настройки, F, минимум 80×24,
  восстановление после resize, три качества, четыре временные палитры,
  устаревшие кадры/события, ошибки parser-task и начальный фокус главного меню.
- Вход в мини-игру не сбрасывает сюжетную музыку и ambience.

### Воспроизведение

```bash
.venv/bin/python -m coverage run --branch \
  --source=card_faces,card_game,card_scene,card_session,card_story,card_table,script_cards \
  -m unittest discover -s tests -p 'test_card*.py'
.venv/bin/python -m coverage report \
  --include='src/card*.py,src/script_cards.py' --fail-under=100 -m
```

Измеряется весь код семи перечисленных модулей, без исключений строк
или ветвей через `pragma: no cover`. Изменения интеграции в `main.py`,
`script_parser.py` и валидаторах проверяются теми же сценариями, но
**не входят** в этот процент: это не 100% покрытия всего проекта.

Карточные наборы также импортированы в агрегатор `tests/test_release.py`.
`tests/` игнорируется локальным `.gitignore`: файлы тестов следует учитывать
отдельно от вывода `git diff`.

## Известные ограничения

- Windows-сборка и работа в Windows-терминале не запускались.
- SDL dummy в smoke-тестах подтверждает управление аудио, но не слышимость.
- Onefile-тесты используют локальные ассеты, не чистую загрузку из облака.
- `tests/test_readme_assets.py` имеет прежний сбой
  `ReadmeCaptureTests.test_wait_frame_is_reproducible_in_both_styles`
  и последующую ошибку `assertNotEqual(*digests)`. На неизменённом `HEAD`
  получены те же границы различий `(100, 949, 1909, 1080)` для ANSI
  и COLOR_ASCII. README и эталонные изображения не изменялись.
- Старые сохранения изменённого `day2.txt` отклоняются штатной проверкой hash.
  Формат 3 для неизменённых сценариев поддерживается; карточные позиции
  используют формат 4. Старые внешние TXT onefile автоматически не обновляет.

Процент покрытия измеряет исполненные строки/ветви указанного кода,
а не гарантирует отсутствие всех ошибок проекта.
